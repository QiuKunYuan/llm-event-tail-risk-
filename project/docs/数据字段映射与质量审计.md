## 2. RESSET 原始字段到标准字段映射

以下为当前 `scripts/prepare_resset.py` 使用的主要字段映射。`ComCd/CompanyCode` 是公司标识，`StkCd` 是证券代码；进入公司日面板时优先以六位 `stock_code + date` 对齐，缺证券代码时才能评估用公司代码回填，不可直接把不同层级代码混用。

| 数据表 | RESSET 原字段 | 标准字段 | 用途 / 注意点 |
|---|---|---|---|
| 日收益 DRET | `上市公司代码_ComCd`、`股票代码_Stkcd`、`交易时股票代码_Stkcdotrd`、`日期_Date` | `company_code`、`stock_code`、`trading_stock_code`、`date` | 个股—日期主面板。A 股代码保留 6 位字符串，不能转整数后丢前导零。 |
| 日收益 DRET | `日收益率_Dret`、`日资本收益率_Daret`、`日无风险收益率_DRfRet` | `return`、`capital_return`、`risk_free_rate` | 标签脚本现用 `return` 和 `risk_free_rate`。缺失个股收益的日观测不用于因子估计或标签窗口。 |
| 日收益 DRET | `流通市值加权平均市场日收益率_Drettmv`、`总市值加权平均市场日收益率_Dretmc` | `market_return_float`、`market_return_total` | 市场收益口径交叉核对；不应与因子表的 Rmrf 当成同一字段。 |
| 日收益 DRET | `证监会行业门类代码_Csrciccd1`、`证监会行业大类代码_Csrciccd2` | `industry_sector`、`industry_group` | 行业控制/分组；历史行业特征需按预测时点已公开的信息构造。 |
| 日三因子 | `日期_Date`、`交易所标识_Exchflg`、`市场标识_Mktflg` | `date`、`exchange`、`market` | 先按标识筛选，再按日期连接。 |
| 日三因子 | `Rmrf_tmv`、`Smb_tmv`、`Hml_tmv` 对应流通市值加权字段；`Rmrf_mc`、`Smb_mc`、`Hml_mc` 对应总市值加权字段 | `rmrf_float`、`smb_float`、`hml_float`；`rmrf_total`、`smb_total`、`hml_total` | Rmrf 是市场溢酬因子（市场收益减无风险收益）。主口径为 `Exchflg=2, Mktflg=A`、流通市值加权；总市值加权用于稳健性。 |
| 行业日收益 | `日期_Date`、`证监会行业门类代码_Csrciccd1`、`行业日收益率_流通市值加权_Drettmv` | `date`、`industry_sector`、`return_float` | 行业收益用于备用标签/稳健性口径；少量缺失需在使用时按窗口完整性处理，不做未来值填补。 |
| 业绩预告 | `上市公司代码_ComCd`、`A股股票代码_A_StkCd`、`信息发布日期_InfoPubDt`、`截止日期_EndDt` | `company_code`、`stock_code`、`publication_date`、`report_date` | `publication_date` 是特征可用时间；`report_date` 仅为业绩对应报告期，不能拿来提前生效。 |
| 业绩预告 | `业绩预测类型_FrcstType`、`业绩预测结果说明_ResStat`、`业绩预测内容描述_FrcstCon`、`预测对象_FrcstObj` | `forecast_type`、`result_summary`、`forecast_text`、`forecast_object` | 文本和数据库已有结构化标签。公告只有日期级发布时间时，从发布后的下一交易日起生效。 |
| 业绩预告 | `EstGroRtFlr/Cei`、`EstPrfFlr/Cei`、`LastProf` | `growth_upper/lower`、`profit_lower/upper`、`last_profit` | RESSET 导出列别名容易让“上限/下限”顺序看起来反直觉；正式使用前以字段词典及样例逐列确认，不自行按名称猜方向。 |
| 诉讼仲裁 | `首次信息发布日期_IInfoPubDt`、`信息发布日期_InfoPubDt`、`公告类型_DclrType` | `first_publication_date`、`publication_date`、`announcement_type` | 预测特征使用信息发布日期；首次发布日期适合描述事件时间，不代表更新内容当时已知。 |
| 诉讼仲裁 | `事件内容_EventCon`、`行为描述_ActDes`、`最新进展状态描述_NewestAdv`、`事件主体_EventSub`、`事件进程_EventProc` | `event_text`、`behavior_text`、`latest_status`、`event_subject`、`event_process` | 当前导出 `event_text` 全空，实际文本在 `behavior_text`；不可把空的 `event_text` 当作无文本事件。 |
| 主要股东 | `上市公司代码_ComCd`、`A股股票代码_A_StkCd`、`截止日期_EndDt`、`信息发布日期_InfoPubDt` | `company_code`、`stock_code`、`report_date`、`publication_date` | 持仓只从 `publication_date` 起可见，不能按报告截止日回填到披露前。 |
| 主要股东 | `股东排名_ShRank`、`股东ID_GDID`、`股东名单_SHLst`、`股东性质_SHChrct`、`股东类别_SHType` | `holder_rank`、`holder_id`、`holder_name`、`holder_nature`、`holder_type` | `SHLst` 是股东名称；`SHChrct` 是性质文本。共同股东主体优先用 `GDID`，缺 ID 的非自然人仅作后续名称匹配候选，须先评估名称稳定性。 |
| 主要股东 | `持股数(股)_HoldSum`、`持股数占总股本比例_PctTotShr`、`持股数占流通股比例_PctTrdShr` | `holding_shares`、`pct_total`、`pct_float` | 初始候选筛选 `holder_rank<=10` 且 `pct_float` 非空；此条件仍需结合原表的股东组别解释，不直接等同“所有机构持仓”。 |
| 行业历史 | `信息发布日期_InfoPubDt`、`生效日期_EffDt`、`取消日期_CancelDt`、行业代码 | `publication_date`、`effective_date`、`cancel_date`、`industry_code/sector` | 未来生效的行业变更公告不能在发布日期前进入特征。 |
| 上市状态历史 | `变更日期_ChgDt`、`变更类型_ChgType`、`变更原因_ChgRea`、`变更说明_ChgStat` | `change_date`、`change_type`、`change_reason`、`change_description` | 当前表只有状态变更历史，不包含完整上市日期/退市日期基本资料，也不能替代完整代码变更表。 |

## 4. 共同股东候选池初审

全期 `holder_rank<=10` 且 `pct_float` 非空的记录有 **1,777,465** 行。其中自然人 768,485 行，应从“机构共同持股”关系中排除。剩余非自然人候选 1,008,980 行中，932,997 行有 `holder_id`，75,983 行缺 ID，缺失比例约 **7.5%**。

以上是流通股口径候选池初审，不是已确定的主图边。固定主图采用完整披露名单、统一总股本比例口径、GDID优先和已核验机构类型；排除个人、名义托管和无法识别主体。新完整名单替换整份旧名单。缺ID不自动模糊合并；保留InfoSource、SHSer与UpDt并核实原始版本。日期级披露下一市场交易日生效。

## 5. 面板拼接与时间规则

1. 日频预测主键为 `stock_code + date`，现有日收益表已确认该键唯一。
2. 公司代码可作辅助映射，不覆盖证券代码。缺失 `stock_code` 的公告/股东行只有在公司代码到证券代码映射唯一且有效时才回填；否则单列未匹配记录，不猜测。
3. 公告采用 `publication_date`；没有可靠时分秒时，统一从发布日后的下一交易日起生效。
4. 股东关系采用 `publication_date`，而不是 `report_date`；预测日只能读取当日收盘前已披露的最新股东记录。
5. 现有日收益到 2024-07-31，故当前标签尾日固定为 2024-07-24。若之后补到更晚日期，先重做全量覆盖审计，再更新配置、标签和所有基线，不能只把配置日期改大。
6. 固定样本不含2025年：日收益实值只到2024-07-31，预测期据此截止。
