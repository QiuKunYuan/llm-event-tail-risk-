# 业绩预告事件语义人工标注规范 v1

## 标注目标

根据 RESSET 的业绩预告内容描述，抽取公告文本表达的预期业绩方向、原文明确给出的原因和支持判断的原文证据。这里的“方向”描述经营/财务业绩，不代表股价方向，也不表示公告导致了未来收益。

每条样本填写三个标签：

```json
{
  "direction": "改善|恶化|基本稳定|混合|不明确",
  "causes": ["文本明确说明的原因；没有则为空数组"],
  "evidence": ["从公告原文逐字复制的证据片段"]
}
```

## 字段定义

### `direction`

- `改善`：预计利润/收入上升、亏损收窄、扭亏为盈，或明确描述经营改善。
- `恶化`：预计利润/收入下降、亏损扩大，或明确描述经营恶化。
- `基本稳定`：明确预期与同期大致持平，且没有更强的改善或恶化方向。
- `混合`：文本明确表达了方向相反且均重要的结果，例如利润改善但收入显著下降；不能仅因公告同时包含多个指标就标混合。
- `不明确`：只有经营计划、原因不清、文本无法读取，或信息不足以判断业绩方向。

判断时优先读完整公告描述。文本含有明确数字时，用数字方向辅助判断；不得只凭 `forecast_type` 数字代码判断，因为当前导出尚未在本项目内建立代码字典。

### `causes`

- 只填写公告明确陈述的原因，简洁概括为短语，例如“主要产品销量增加”“原材料成本上升”。
- 不把结果改写成原因；不推测文本没有说的原因。
- 多个原因分别成项；没有明确原因时填写 `[]`。

### `evidence`

- 填 1–3 段支持方向或原因判断的原文片段，必须能在输入正文中逐字找到。
- 优先引用最短但足以支持标签的句子；不得改写、补充背景或引用数据库元数据。
- 若 `direction=不明确`，可引用说明信息不足的原文；若文本为空则该样本不应进入标注集。

## 操作步骤

1. 先读完整的 `forecast_text`，不要从公司代码或日期推测结果。
2. 独立填写 `direction`、`causes_json`、`evidence_json`。两个 JSON 列都必须是合法 JSON 数组，例如 `[]` 或 `["原因一"]`。
3. 低置信度或文本截断时，在 `annotator_note` 记录原因，并将 `needs_adjudication` 填 `yes`。
4. 主标注者完成 300 条；第二名标注者只对双标文件中的 60 条独立标注。双标者不查看对方结果。
5. 对 60 条双标样本，先计算方向一致率和 Cohen’s Kappa，再讨论分歧并形成裁决标签。不要先讨论再独立标注。

## 易混情况

- 预告中的“增长/下降”是相对上年同期，不是股票收益。
- “亏损减少”标为 `改善`；“盈利减少”通常标为 `恶化`。
- 文本只有盈利数值、没有比较基期或方向词时，结合上下文判断；仍无法判断则标 `不明确`。
- 原因写“非经常性损益影响”但没有具体解释时，可将其作为原因，不可自行补成具体事件。
- 一份公告中若同时描述多个不同报告期，标注主体以公告对当前预测期的主要结论为准；确实无法确定时标 `混合` 或 `不明确` 并写注释。

## 本轮试标用途

300 条试标用于发现标签定义歧义、评估人工一致性和试跑 SFT 数据流程，不代表最终模型评测集。样本按年份和 RESSET 预测类型分层抽取；建议切分为 2017–2021 训练、2022 验证、2023–2024-07 测试。最终训练前应增加人工核验样本，并按披露事件去重，避免同一事件跨集合。
