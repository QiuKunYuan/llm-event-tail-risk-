# 公告事件抽取与 QLoRA 微调运行说明

## 当前模型任务

Qwen3-1.7B 只负责从业绩预告正文抽取结构化事件语义，不预测股票收益。输入仅含公告正文；输出固定 JSON：

```json
{
  "direction": "改善|恶化|基本稳定|混合|不明确",
  "causes": ["公告明确陈述的原因"],
  "evidence": ["公告正文中的逐字证据"]
}
```

RESSET 已有的业绩预测类型和数值区间不交给 LLM 重复抽取，后续作为独立结构化特征保留。方向表示预期经营/财务业绩，不表示股票涨跌。

## 目前准备好的人工标注包

样本由 `scripts/prepare_announcement_annotations.py` 固定随机种子 20261110，从当前标签期内按“发布日期年份 × RESSET 预测类型”分层抽样，并去掉同公司、同发布日期、同报告期、同类型、同正文的精确重复记录。实际导出了：

- `outputs/annotations/earnings_pilot_300_annotator_a.csv`：300 条主标注模板。
- `outputs/annotations/earnings_pilot_060_annotator_b.csv`：其中 60 条双人复核模板。
- `outputs/annotations/sampling_report.json`：抽样数、分层和排除记录统计。

标注规则见 [`公告人工标注规范-v1.md`](公告人工标注规范-v1.md)。主标注者填写 A 文件；另一位标注者独立填写 B 文件的 60 条。对分歧样本裁决后，把 A 文件中的最终值写入 `direction`、`causes_json`、`evidence_json`，并把待裁决行的 `needs_adjudication` 清空或填 `no`。每条原因和证据都要使用合法 JSON 数组；证据必须能在正文中找到。

当前抽样文件在 `project/outputs/annotations/`，被 Git 忽略，包含 RESSET 正文，不应提交到公开仓库。

## 生成 SFT 训练集

人工标注完成后，在项目仓库根目录执行：

```bash
python3 project/scripts/build_sft_dataset.py \
  --input project/outputs/annotations/earnings_pilot_300_annotator_a.csv \
  --output-dir project/outputs/sft_dataset
```

程序会验证标签枚举、JSON 格式、证据片段是否来自原文，并按发布日期拆分：2017–2021 为训练集，2022 为验证集，2023–2024-07 为测试集。输出为 `train.jsonl`、`validation.jsonl`、`test.jsonl`。尚未裁决的样本会跳过；空标签、重复记录 ID 或不在原文中的证据会报错，不会静默混进训练集。

300 条是标注规范与流水线试验集，174/40/86 的临时切分不足以支撑最终结论。正式报告模型 F1 之前，应按同一规范把人工金标准扩至约 600–1,000 条，并确保验证、测试样本按时间留后。

## 在租用 GPU 上运行 QLoRA

当前工作环境没有可用 CUDA GPU，未安装微调依赖；这一步应在租用 GPU 机器上执行。先把仓库代码和经授权的标注 JSONL 安全复制到该机器，并按该机器 CUDA 版本安装 PyTorch，再安装：

```bash
python -m pip install -r requirements-qlora.txt
```

单卡 Qwen3-1.7B、4-bit NF4、LoRA rank 16 的初始命令：

```bash
python project/scripts/train_qlora.py \
  --train project/outputs/sft_dataset/train.jsonl \
  --validation project/outputs/sft_dataset/validation.jsonl \
  --test project/outputs/sft_dataset/test.jsonl \
  --model Qwen/Qwen3-1.7B \
  --output-dir project/outputs/qwen3-1.7b-qlora \
  --max-length 2048 \
  --epochs 3 \
  --batch-size 1 \
  --gradient-accumulation 8 \
  --lora-rank 16 \
  --lora-alpha 32 \
  --compute-dtype bf16
```

显卡不支持 bfloat16 时改用 `--compute-dtype fp16`。脚本会在验证集 loss 最优的 epoch 保存 LoRA adapter，并记录训练/验证/测试数量、超长样本跳过数和 loss。先用 1.7B 做小规模可行性试验；如果有效，再讨论增加标注或尝试 Qwen3-4B/8B。

微调后单独在留出的人工测试集上做结构化生成评价：

```bash
python project/scripts/evaluate_event_extractor.py \
  --data project/outputs/sft_dataset/test.jsonl \
  --model Qwen/Qwen3-1.7B \
  --adapter project/outputs/qwen3-1.7b-qlora/best_adapter \
  --output-dir project/outputs/event_extractor_eval \
  --compute-dtype bf16
```

报告包括严格 JSON 可解析率、方向准确率/宏平均 F1、原因短语严格匹配、证据片段严格匹配，以及模型生成的证据是否能在输入正文中找到。原因和证据严格匹配偏保守，需结合人工复核；不能单独以验证 loss 下降宣称抽取有效。

## 训练前的停止条件

- A/B 两份人工标注尚未完成或双标分歧尚未裁决：不训练。
- 证据字段不是原文片段、标签用法不一致或低置信度样本过多：先修标注规范并返工。
- 试标只有 174 条训练样本：可以做流水线冒烟式模型试验，但只能称为探索性结果，不能作为最终抽取性能结论。
- 微调后必须在独立时间留后人工测试集上报告方向分类指标、严格 JSON 可解析率和证据匹配情况；验证 loss 下降本身不等于抽取效果提升。
