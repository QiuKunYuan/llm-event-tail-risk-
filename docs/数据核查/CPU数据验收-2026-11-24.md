## 2. 标签怎么独立核验

### 2.1 两种检查必须区分

第一种是**生产算法全量复现**：使用现有C++生成器，从9,091,641条DRET重新拟合滚动回归与标签，输出另存目录。输入、Python/C++代码、加工报告和输出都有SHA256；运行前后检查输入/代码未变化。旧标签不覆盖，生成器现在拒绝覆盖已有标签或报告。

第二种是**独立算法抽样参照**：NumPy使用`linalg.lstsq`的SVD最小二乘，每个起点直接重新拟合252条原始设计矩阵观测，不复用C++的增量正规方程。20家公司由短有效历史、多缺失、多缺市场日和固定种子分散抽样构成，不按未来风险标签选公司。明细仅保存在私有目录。

参照按完整市场日历检查未来五日；历史阈值只使用结果已经结束的最近252个窗口，P10取第26项、P5取第13项，严格小于为正类。收益、无风险收益或任一因子不有限，都不能进入回归或未来窗口；预测日起点自身缺失可保留标签，但序列必须携带掩码。

## 3. 四折共享索引

### 3.1 结构与约束

`company_day_index.csv.gz`保留全部标签公司日，字段为：

```text
index_id, stock_code, date, outcome_end, outcome_end_ordinal,
label_p10, label_p05,
split_2021, split_2022, split_2023, split_2024-partial
```

- `index_id`是该版本CSV的0起始行号，由整个索引哈希定义，不是跨数据版本永不变化的ID。
- 四个split列分别使用`train / validation / test / purged / out_of_range`。每折按对应列过滤，不物化四份重复公司日表。
- 论文P5对应实际字段`label_p05`，不擅自改成`label_p5`。
- 市场日历来自全量DRET，`outcome_end`为预测日起第五个未来市场日；ordinal与现有NPZ训练入口兼容。
- 训练结果结束日严格早于验证首个实际市场日；验证结果结束日严格早于测试首个实际市场日。边界purge与范围外记录分开。
- 不按公告或图是否可用删除公司日；后续模型均须使用相同键集合。
- 测试期限定预测起点，不要求测试标签结果也在同一日历年结束。最后2024-07-24起点的结果结束于2024-07-31，使用已存在收益，不延长研究期。

## 4. 股东重复排名：不是简单去重

### 4.1 重复单位与字段差异

全量4,036,775行中，3,909,902行满足Top10及公司/报告期/公开日/来源组键。形成206,223个候选组，189,735组有重复排名，与前次审计计数一致。

本次进一步以“候选组＋排名”为重复单位，共1,753,196个重复单位。这里只比较原始姓名/ID字符串相等，不自动合并机构，不以名称相等认证主体。

| 字段证据 | 重复单位或候选组数量 |
|---|---:|
| 同排名非空姓名全部相同的重复单位 | 979,175 |
| 同排名姓名不同的重复单位 | 774,021 |
| 同排名非空ID全部相同的重复单位 | 563,765 |
| 重复单位至少一行缺ID | 988,684 |
| 同排名出现多个不同非空ID的重复单位 | 214,389 |
| 所有保留字段完全重复的单位 | 19,518 |
| 除SHSer/UpDt外字段完全相同的单位（含完全重复） | 24,704 |
| 持股数或总/流通比例至少一项不同的单位 | 1,709,961 |
| 同排名存在姓名或非空ID冲突的候选组 | 118,851 |
| 20行且排名1—10各出现两次的组 | 136,908 |

160,294组恰20行，但只有136,908组恰好每个排名出现两次。因此“20行就是两份十股东名单”的推断不成立。持股内容和身份差异普遍存在，也不是删除完全重复行即可解决的问题。

同排名的公司总股数/流通股总数无差异，但`holding_shares`在790,992个单位有差异，`pct_total`在790,874个单位有差异，`pct_float`在1,707,715个单位有差异。这支持继续核对名单口径与来源，尚不能认证每行属于哪份名单或何种修订。

### 4.2 SHSer、UpDt和SHType不能充当捷径

SHSer在3,680,533个候选行与排名相等。加入SHSer拆组仅使13,877个重复组排名不再重复；加入UpDt仅解决5,273组。它们既不能解决所有重复，也不能凭此认证名单类别或历史公众可见时间。

加入`holder_type`可使123,097个重复组排名唯一，但这是危险的伪捷径：原`SHType`聚合值是“其他股东”2,009,384行、“国有股东”249,142行、“外资股东”110,783行、空值1,667,466行，合计全量4,036,775行。它描述股东类别，不是总股东/流通股东名单类型。不能因拆后排名唯一就把它当成完整名单组键。

### 4.3 比例单位已得到数值核验

初次检查只尝试百分数尺度，匹配很少，因此重跑为**比值与百分数两种单位假设**，不根据字段名称猜单位。新结果：

- 全部3,909,902个候选行，`pct_total`都在[0,1]，且与`holding_shares / total_shares`在绝对`1e-6`内一致。
- `pct_float`数值可用的1,772,298行全部在[0,1]，且与`holding_shares / float_shares`在同容差内一致。
- 百分数假设`100 × 持股数 / 股数`在等价容差`1e-4`百分点下仅匹配总比例218行、流通比例13行，不能据此定义全表尺度。

因此**当前加工CSV已经是0—1比值，真实图适配不能再除以100**。正式论文仍须引用来源词典解释原字段；数值单位一致不等于名单完整或历史版本可靠。

### 4.4 当前图仍不放行

`main_graph_ready=false`。尚缺原名单类型、完整公开来源、修订公众可见证据、机构主体及产品/管理人边界认证。新完整名单替换整个旧列表的规则不变；不得把未知组写成`complete=True`，不得任取十行或按最新数据库更新时间回填历史。
